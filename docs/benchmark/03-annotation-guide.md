# 盲听标注指导语（给标注者）

> 你拿到的是一份标注清单（sheet）和一组候选歌手的试听样本。请**只用耳朵**判断，
> 不要试图找出"系统推荐了谁"。

## 用标注界面（推荐）

1. 用浏览器打开 `annotation-ui.html`（无需联网、无需安装）。
2. 点"选择基准集目录"，选中包含 `sheet.json`、`samples/` 和查询录音的文件夹。
3. 填你的标注者 ID，逐条听查询、点候选歌手试听、勾选最像的 1–2 位（或"都不像"）。
4. 可随时"保存进度到本机"，下次用"载入进度"接着标。
5. 全部完成后点"导出 annotations.json"，把导出的文件交给组织者。

> 若某位候选显示"无试听样本"，说明该歌手的素材没有可用发声窗，跳过试听、凭印象判断即可。
> 若弹出"最多选 2 位"，请先取消一位再选——这是任务规则（只选最像的 1–2 位）。

## 若被通知做 pairwise 重标

当第一轮标注一致性不足，会改用比较式提问。在界面切到"pairwise 比较"模式：

1. 每条任务会播放同一段查询录音，以及 A、B 两位歌手各一段样本。
2. 点"选 A 更像"或"选 B 更像"；实在分不出就点"分不出 / 都不像"。
3. 完成后导出 `pair-annotations-<id>.json` 交给组织者。

> 比较式提问只问"这两个谁更像"，比 8 选 1 更容易判断——不要试图套用上一轮的多选结果。

---

## 你的任务

对清单里的每一条录音：

1. 听一段清唱录音（约 8–12 秒）。
2. 清单会列出 8 位歌手，点击每位歌手可试听其一段清唱样本。
3. 从 8 位里选出**最像这段录音的 1–2 位**歌手；如果你觉得**都不像**，就选择"都不像"。
4. "都不像"是一个正当答案——它可能说明歌手库里没有声线接近的人。

## 重要规则

- **不要猜哪个是"正确答案"**：8 位歌手的顺序是打乱的，系统自己的排序对你不可见，也没有所谓的标准答案。
- **凭整体听感**：音色、音高、共鸣、唱腔都可以作为依据；不需要声乐专业知识。
- **独立判断**：不要和其他标注者讨论，也不要参考他们的选择。
- **可以不确定**：如果拿不准，选最接近的 1 位，或选"都不像"。

## 你不需要做的事

- 不需要给相似度打百分比分数。
- 不需要排序全部 8 位——只选最像的 1–2 位即可。
- 不需要知道录音者是谁（身份信息已脱敏）。

## 提交

完成后把你的标注结果（每条 query 的 query_id + 选中的歌手 id，或空表示"都不像"）交给组织者。

---

## 组织者须知（不要发给标注者）

- 每条 query 由 3 位标注者独立完成；系统按严格多数裁决（>半数票）。
- 标注完成后计算 Cohen's kappa；若均值低于门槛（默认 0.6），说明问法不稳，
  应改用 pairwise 比较式提问重新标注，而不是调低门槛掩盖问题。
- 首选不一致的 query 会记入 MANIFEST 的 `disputed_queries`，供专业小组二次校验。
- "都不像"占比过高是扩库信号（库覆盖不足），不是调阈值的理由。
