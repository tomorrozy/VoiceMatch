# 招募与筛选（真人盲听基准集）

> 这份文档解决一个具体问题：**怎么在 3 天内凑到 12 位愿意录 3 段清唱、并且真的能录成的人**。
> 采集规范见 `02-capture-checklist.md`，同意书见 `01-consent-form.md`，标注见 `03-annotation-guide.md`。
> 顺序不能颠倒：先签同意书，再录音；先过筛选，再约时间。

---

## 一、先定规模与配额

| | Pilot | 正式 |
|---|---|---|
| 人数 | 10–15 | 60–100 |
| 条数（每人 3 段） | 30–45 | 180–300 |
| top1 的 95% CI 半宽（按人聚类后） | ≈ ±0.18 | ≈ ±0.07 |
| 用途 | 验证流程、界面、kappa ≥ 0.6 | 对外报准确率 |
| 周期 | 2–3 天 | 3–5 周（招募占八成时间） |

**配额不是"男女各一半"就够。** 录音要覆盖下面四个维度，否则结论只能代表某一类人：

| 维度 | 要求 | 为什么 |
|---|---|---|
| 性别 | 各 50%（±10%） | 候选池按性别分开，池大小不同会直接改变随机基线 |
| 年龄 | 18–25 / 26–35 / 36–50 各占约 1/3 | 音色随年龄变化，全招同龄人会让 top1 偏乐观 |
| 设备 | 每人 3 段中至少 2 种 device_id | G3 跨设备稳定性必须有分母 |
| 声线 | 至少各 3 人自评"偏低/中等/偏高" | 避免全是明亮嗓音，导致单调性偏差 |

> 不要招"唱得好的人"。产品用户就是普通人，招歌手会让指标虚高且不可迁移。
> 但**要**排除"唱不出连续 10 秒"的人——那不是模型问题，是采集问题。

## 二、招募顺序：先熟人，后公开

1. **熟人/同事（最快）**：当天能约到 5–8 人，用于 Day 1 打通流程。
2. **内部群/兴趣群（次快）**：一天内凑齐剩余名额，注意不要在同一个群招太多（同群往往同年龄段）。
3. **公开渠道（最后）**：公开招募响应率低（约 5–10%），且需要更完整的隐私说明，放最后。

## 三、三条触达话术

**A. 群公告（一句话说清成本，降低决策门槛）**

> 我们在做"你唱歌像谁"的准确性测试，需要真人录 3 段清唱，**全程约 5 分钟**：
> 每段 20 秒左右，不用伴奏、不用唱得好，手机录就行。
> 声音只用于这次测试，会匿名处理，**随时可以要求删除**；有 [补偿方式]。
> 想参加的回复"1"，我私信发你同意书和录制入口。

**B. 私信（把"要做什么"讲成动作，不讲技术）**

> 想请你帮个忙，5 分钟：
> 1）先看一页同意书，勾两个选项（评估用途必选，训练用途默认不同意）；
> 2）用手机录 3 段清唱，随便唱，每段 20 秒；
> 3）第 2、3 段换个地方或换副耳机录，这点很重要。
> 录完把文件发我，或者我发你一个链接直接传。不方便的话完全没关系。

**C. 当面/现场（给一个可照读的开场）**

> "这个测试是判断'你的声音最像哪位歌手'，我需要你清唱几句，不用好听，正常唱就行。
> 一共 3 段，每段 20 秒左右。第 1 段在这儿录，第 2 段我们换个房间，第 3 段用你的手机录。
> 录音只用于这次测试，不做别的用途，你随时可以让我删掉。"

**不要说的话**（会造成后续纠纷或数据偏差）：

- "很快就好了"——实际要 5–8 分钟，说少了会让人赶时间、录出废段。
- "唱得像某位明星就入选"——这是评估，不是选秀，会诱导人模仿。
- "以后可能用于训练 AI"——除非本人单独勾选了训练用途；默认不同意。

## 四、筛选问卷（5 问，30 秒）

按顺序问，任一条命中排除项就不约录音，改为约"反例集"（见第七节）。

| # | 问题 | 处理 |
|---|---|---|
| 1 | 你能连续唱 10 秒以上、不用伴奏吗？ | 不能 → 排除（无法通过发声门槛） |
| 2 | 录音环境能安静到没有明显背景音吗（关窗、关风扇）？ | 不能 → 改约安静时段，仍不行 → 排除 |
| 3 | 是否愿意签署同意书（评估用途必选）？ | 不愿 → 排除，不做说服 |
| 4 | 年龄段？（18–25 / 26–35 / 36–50 / 其他） | "其他"（未满 18）→ 需监护人同意，pilot 阶段直接排除 |
| 5 | 手机型号 + 是否有耳机？ | 用于分配 device_id，并保证同一人 3 段不全是同一设备 |

补充两条只登记、不筛选：性别（候选池需要）、自评声线高低（分层用）。

## 五、排期模板（Pilot，3 天）

| 时间 | 动作 | 产出 |
|---|---|---|
| D1 上午 | 发群公告 + 私信，收 15 人报名 | 报名表（含问卷答案） |
| D1 下午 | 按配额挑 12 人，发同意书，约时段 | 12 份已签同意书 |
| D2 全天 | 每人 10 分钟，录 3 段（每 30 分钟 3 人） | `audio/*.wav` + `specs.json` |
| D2 晚 | `preflight` 校验，补齐不合格的段 | 0 error 的 specs |
| D3 上午 | 补录 2–3 人（预留 buffer，通常有 20% 爽约） | 12 人齐全 |
| D3 下午 | 3 位标注者盲听 + kappa | `annotations/*.json` |

**预留 20% 爽约缓冲**：约 12 人要招 15 人。这不是保守，是经验值。

## 六、补偿、隐私与合规

- **补偿**：按时间给（例如一杯咖啡/等价红包），**不与"录得好"挂钩**，否则会诱导人反复重录、挑最好的交。
- **隐私**：`subject_id` 用代号（`p001`），真实姓名只出现在同意书纸质件；`specs.json` 里不写姓名、手机号。
- **存储**：录音放加密盘或受控目录，`material/` 不入 git（已在 `.gitignore`）。
- **删除**：同意书写明删除渠道；冻结后的基准集要能按 `subject_id` 定位并删除对应行，删完重跑 `freeze` 生成新版本，不要手改 `eval_set.json`。
- **权利声明**：若歌手库仍是 M4Singer（CC BY-NC-SA），即使录音是你自己的，**本次基准的结论仍只能用于研究**；要对外报准确率，必须换成可商用的歌手库。这条在 `frozen/MANIFEST.json` 的 `rights` 里是机器可读的。

## 七、反例集：别把"该拒答"当失败

跑调、极小声、嘈杂环境、变声期、老年嗓音这些样本，**不进主指标**，但要单独收 10–20 条，
交 2 人按质量 rubric 标"应拒答"，用来验证拒答是否合理（设计 6.4）。
主指标里混入这些样本，会让 top1 变得无法解释。

## 八、常见拒绝与处理

| 说法 | 处理 |
|---|---|
| "我唱歌很难听" | "正需要难听的，测试的就是普通人的声音。"（真实且有效） |
| "会不会被传到网上" | 说明只用于内部评估、匿名、可删除；不承诺"绝对安全"，说明具体措施 |
| "要多久" | 给真实数字：5–8 分钟，含同意书 |
| "能不能不露脸/不说话" | 本来就不需要露脸，只需要清唱 |

## 九、与工具链的衔接

录完只做两件事，剩下的交给脚本：

```bash
# 1) 登记（字段照 02-capture-checklist.md 填）
#    audio/p001-a.wav + specs.json 里一行
python tools/benchmark_run.py preflight --dir material/benchmark   # 查重名/时长/性别/路径
python tools/benchmark_run.py run --dir material/benchmark --steps diagnose,samples,sheet

# 2) 3 人盲听后，把导出的 annotations-<id>.json 放进 annotations/
python tools/benchmark_run.py status --dir material/benchmark      # 告诉你下一步
python tools/benchmark_run.py merge  --dir material/benchmark
```

`preflight` 会拦下两类最贵的错误：**音频重名**（界面按文件名匹配，会串音）和
**短于 8 秒**（永远过不了受理门槛）。这两类错误在标注完成后才发现，返工成本是重录 + 重标。
